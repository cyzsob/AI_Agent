# RAG 项目面试题

> 基于本项目（DeepSeek + LangGraph ReAct Agent + PGVector + BM25 混合检索 RAG 系统）的实现细节整理

---

## 一、架构设计

### 1. 整体架构
- 描述本项目的整体架构，包含哪些核心模块？各模块之间的调用关系是怎样的？
- 本项目从"固定 RAG 链路"升级到"Agent 自主决策"解决了什么问题？两者各自适用什么场景？
- 为什么选择 LangGraph 的 `createReactAgent` 而不是 LangChain 的 `AgentExecutor`？两者的核心区别是什么？

### 2. 技术选型
- 项目中使用 `@napi-rs/canvas` 替代 `node-canvas` 的原因是什么？这对 Windows 环境部署有什么意义？
- 为什么选择 `lunr` 做 BM25 检索而不是 `elasticsearch` 或 `meilisearch`？这种选择的代价是什么？
- 嵌入模型选择 `bge-m3` 而不是 OpenAI `text-embedding-3-small` 的考量是什么？
- 向量数据库选择 PostgreSQL + pgvector 而不是专门的向量数据库（如 Milvus、Pinecone）的优缺点是什么？

## 二、文档解析

### 3. PDF 混合解析策略

- 为什么 `fs.readFileSync` 返回的 `Buffer` 需要显式转为 `new Uint8Array(buffer)` 才能给 pdfjs-dist v6 使用？
- 智能合并策略中如何判断一个 PDF 页面是"文字型"还是"扫描件"？合并逻辑中为什么选择 80 字符作为阈值？
- 渲染 PDF 页面时使用 `scale: 2.0` 的原因是什么？如果改成 `scale: 1.0` 会有什么影响？

### 4. OCR 实现

- 如果 PDF 中包含公式或代码块，当前的解析策略会有什么问题？你会如何改进？

## 四、混合检索

### 6. 向量检索
- 向量检索的 embedding 模型 bge-m3 输出多少维向量？这维度的选择对检索性能和准确率有什么影响？
- OllamaEmbeddings 的 `baseUrl` 配置为 `http://localhost:11434`，如果 Ollama 服务不可用，系统会如何表现？如何改进？

### 7. BM25 检索
- 项目中中文 BM25 的分词策略是什么？为什么要在汉字前后插入空格？
- `this.pipeline.remove(lunr.stemmer)` 的作用是什么？如果不移除 stemmer，对中文检索会产生什么影响？
- lunr 的 BM25 实现是纯内存索引，数据量大时（如 10 万+ 文档）会面临什么问题？你会如何优化？

### 8. RRF 融合
- 解释 RRF（Reciprocal Rank Fusion）的公式和参数含义：`score = vectorWeight / (rrfK + rank_vector) + bm25Weight / (rrfK + rank_bm25)`
- `rrfK: 60` 这个值的作用是什么？如果设置得太小（如 1）或太大（如 200），分别会有什么影响？
- `vectorWeight: 0.5, bm25Weight: 0.5` 表示两路检索权重相等。什么场景下应该调整这个权重比例？
- 向量检索和 BM25 检索分别擅长什么类型的查询？RRF 融合相比简单拼接结果好在哪里？
- 为什么使用 `Promise.all` 并行执行两路检索而不是串行执行？你认为在实际生产环境中还有什么可以优化的点？

## 十、综合与扩展

### 19. 场景题
- **场景一**：用户提问 "DeepSeek V4 和 GPT-4 相比在数学推理方面谁更强？" — Agent 应该调用哪些工具？检索到的信息可能不足以回答时，Agent 应该如何处理？

- **场景三**：生产环境中，发现某个关键词的 BM25 检索结果很差（相关文档排名靠后），但向量检索结果不错。你会如何分析这个问题的根因？是分词策略的问题，还是 RRF 权重的问题？
- **场景四**：用户连续提问（多轮对话）：
